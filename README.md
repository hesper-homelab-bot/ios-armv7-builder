# ios-tmux-builder

Build **tmux** for a jailbroken **32-bit iOS** device (`armv7`, iOS 10.x) on a
**Linux host**, with no Xcode, no macOS and no iOS SDK.

The output is a Mach-O `armv7` executable whose minimum OS is `10.3`, linked
against the device's own `libSystem` and its shipped `libncursesw`.

```console
$ ./build.sh                     # newest tmux release
$ TMUX_VERSION=3.5a ./build.sh   # a pinned one
```

## Why this is not just `./configure && make`

Cross-compiling a POSIX program to old iOS from Linux means fighting four
separate things at once:

1. **No SDK.** There are no iOS headers on a Linux box, so a sysroot has to be
   assembled by hand. This project starts from [musl]'s headers and then
   corrects every place where the Darwin ABI differs.
2. **The Darwin ABI is not the Linux ABI.** Types, structures, signal numbers
   and even the names of `errno` and `stderr` differ. Getting one wrong gives
   you a binary that links but misbehaves at runtime.
3. **`ld64` only reads Darwin archives.** A static library produced by GNU `ar`
   is rejected outright (`archive has no table of contents`).
4. **`configure` lies when the linker is permissive.** Because undefined
   symbols are allowed (they resolve from the device at runtime), every
   `AC_CHECK_FUNCS` probe reports success — including for functions iOS does
   not have.

## Requirements

| | |
|---|---|
| Host | Linux (tested on Ubuntu 26.04, x86_64) |
| Compiler | `clang` that can target `armv7-apple-ios10.3` (any recent LLVM) |
| Linker | [cctools-port]'s `ld64` (`x86_64-apple-darwin*-ld`), plus its `libdispatch`/`libtapi` on `LD_LIBRARY_PATH` |
| Archiver | `llvm-ar` (must be able to write `--format=darwin`) |
| Device | a jailbroken 32-bit iOS device reachable over SSH — its ncurses headers and `libncursesw.5.dylib` are copied off it |

```sh
export LD64=/path/to/x-ld64/bin/x86_64-apple-darwin13.4.0-ld
export LD64_LIBS=/path/to/x-libdispatch/lib:/path/to/x-tapi/lib
./build.sh DEVICE=ipad        # DEVICE is an ssh host alias for the device
```

## Installing the result

### From the APT/Cydia repository (OTA)

BigBoss stopped accepting new packages, so the build publishes its own
repository (hosted on GitHub Pages, generated by `scripts/make-repo.sh`):

```
https://hesper-homelab-bot.github.io/ios-tmux-builder/repo
```

Add it in Cydia/Sileo, or on the command line as root:

```sh
echo "deb https://hesper-homelab-bot.github.io/ios-tmux-builder/repo stable main" \
    > /etc/apt/sources.list.d/ios-tools.list
apt-get update && apt-get install tmux
```

Releases are also downloadable directly from the
[Releases page](https://github.com/hesper-homelab-bot/ios-tmux-builder/releases).

### Bonus: `tweak/nocablewarn`

A tiny MobileSubstrate tweak that suppresses the "可能不支持此配件 / This
accessory may not be supported" alert SpringBoard shows for non-MFi charging
cables.  It hooks `-[SBUIController
setIsConnectedToUnsupportedChargingAccessory:]` and forces the flag to NO —
note this only silences the alert; whether the device charges from an
unauthenticated cable is decided by the Tristar chip in hardware.  Verified
against the device's own AppleSmartBattery node: the A/B test (tweak
installed vs removed, `ioreg -w0 -l -n AppleSmartBattery`) shows identical
`ExternalConnected` behaviour, so the tweak is cosmetic by design.

The hook class is hard-coded because `objc_copyClassList` aborted the ObjC
runtime on this device when called from a tweak constructor; the owner class
was found statically with `llvm-otool -o SpringBoard`.

### Manual

The binary must be signed, or iOS kills it on launch:

```sh
scp out/tmux-3.5a-armv7 root@<ipad>:/var/mobile/tmux
ssh root@<ipad> 'chmod +x /var/mobile/tmux && ldid -S /var/mobile/tmux'
ssh root@<ipad> '/var/mobile/tmux -V'
```

## How it works

```
build.sh
 ├─ make_sysroot      musl headers  +  sysroot-overlay/   → tmp/sysroot
 ├─ get_ncurses……     scp headers and libncursesw off the device
 ├─ build_libevent    configure + patches/event-config.h + fixups
 ├─ build_tmux        configure, then patch the Makefile, then make
 └─ generate stub     collect undefined symbols → libSystem.tbd → relink
```

### The sysroot overlay

`sysroot-overlay/usr/include/` contains every header that had to be corrected.
The interesting ones:

| file | what had to change |
|---|---|
| `bits/alltypes.h` | `size_t`/`ssize_t`/`ptrdiff_t`/`wchar_t` from the compiler builtins; `time_t` and `suseconds_t` are 32-bit `long`; `_REDIR_TIME64` off; `sigset_t` is 32-bit |
| `sys/stat.h` | Darwin's `struct stat` layout |
| `signal.h` | Darwin's `struct sigaction` (no `sa_restorer`), `sys_signame` |
| `bits/signal.h` | Darwin signal numbers and `SA_*` / `SIG_BLOCK` values |
| `errno.h` | `errno` is `(*__error())`, not `__errno_location()` |
| `stdio.h` | `stdin`/`stdout`/`stderr` are `__stdinp`/`__stdoutp`/`__stderrp` |
| `sys/event.h` | the whole kqueue interface (Darwin layout, including `ext[4]`) |
| `libproc.h`, `mach/mach.h`, `Availability.h` | minimal stubs for the Darwin-only APIs tmux touches |
| `unistd.h`, `netdb.h`, `netinet/*`, `fcntl.h` | missing declarations and network types |

### The compiler wrapper

`tools/cc-wrapper.sh` compiles with `clang` and links with `ld64`. Two rules
matter more than they look:

* **Never force `-o`.** `-c foo.c` must leave `foo.o` where autoconf expects it,
  and `-E` must write to stdout. A wrapper that always passes `-o` makes every
  single configure check report "no".
* **All undefined symbols are allowed.** They are resolved from the device's
  dylibs at runtime. `-lSystem`, `-lc`, `-lm`, `-lpthread` and `-lncurses` are
  therefore ignored; only `-levent` is linked for real.

### The `libSystem.tbd` step

The first link always succeeds (undefined symbols are fine), which gives us the
list of symbols the binary needs. `build.sh` turns that list into a
`libSystem.tbd` stub and relinks. This binds those symbols to libSystem as
*two-level* references. Without it, dyld follows libSystem's re-export of
`libgcc_s.1.dylib` and aborts on iOS 10 with:

```
re-exported symbol 'unknown' not found for image libgcc_s.1.dylib
```

### tmux Makefile fixups

`patches/fixups.sh` applies these after `configure`, all for the reason in
point 4 above — the functions were probed successfully but do not exist on
iOS 10, so the project's own bundled implementations are used instead:

`explicit_bzero`, `setproctitle`, `freezero`, `getdtablecount`, `imsg`,
`fdforkpty` (provides `getptmfd`), `htonll`, `ntohll`

It also adds `-I./compat` (tmux's `compat.h` includes `<imsg.h>`), and links the
device's `libncursesw` directly.

## Status: everything works

Verified on an iPad 4 (iPad3,4, `armv7`, iOS 10.3.3, jailbroken), from a clean
`./build.sh` run, deployed with `ldid -S`:

| check | result |
|---|---|
| `./tmux -V` | `tmux 3.5a` and `tmux 3.8` both build and pass |
| `new-session -d "<cmd>; exec sleep 900"` | exits 0 immediately, pane command runs |
| `ls`, `list-windows`, `list-panes`, `display-message` | correct output |
| `run-shell "<cmd>"` | runs |
| `send-keys "<cmd>" C-m` / `Enter` | submits to the pane |
| `capture-pane` | correct |
| `split-window`, `new-window`, `kill-session` | work |
| `attach` (interactive) | renders, keys work |
| `exit` from an attached session | client returns cleanly |

The only difference from upstream tmux source is the **event backend choice**
(poll instead of select); everything else that matters lives in the sysroot
headers.

## The bug that hid them all: `O_NONBLOCK`

Worth reading even if you never build for iOS, because it produced weeks of
blaming the wrong layer.

The sysroot started from musl, whose `fcntl.h` is Linux's:

```
musl/Linux:  O_NONBLOCK = 0x800     (and O_CLOEXEC = 0x80000)
Darwin:      O_NONBLOCK = 0x4       (and O_CLOEXEC = 0x1000000)
```

`fcntl(fd, F_SETFL, 0x800)` on Darwin sets an unrelated bit and *does not set
non-blocking mode* - and fcntl never fails on an unknown flag, so every
"make this socket non-blocking" in the entire program was a **silent no-op**.
Every socket stayed blocking.

Symptoms this one constant produced:

* the client hung forever inside libevent's signal-pipe drain loop
  (`evsig_cb` reads until EAGAIN; on a blocking fd with no data left it simply
  blocks, and the client never called `poll()` again - proven with a watchdog
  and a debug `poll()` wrapper);
* a peer's data sat unread while both processes were alive and sleeping;
* `MSG_EXIT` was queued but the peer never saw it;
* behaviour changed randomly between runs and between the select/kqueue/poll
  backends, because blocking fds make every event-loop race resolve
  differently.

`F_GETFL`/`F_SETFL` (3/4) match Darwin by pure luck, which is why fcntl calls
never failed loudly. `O_CLOEXEC` being wrong also leaked fds into pane
children.

## The event backend: kqueue really is broken with ttys

Stock tmux force-disables kqueue and poll on Darwin with the comment that they
"don't work on anything except socket file descriptors (yes, really)". On iOS
10 that is literally true, and a minimal libevent program on the device
reproduces it exactly:

| fd set contents | kqueue | poll |
|---|---|---|
| listen socket + socketpairs only | PASS | PASS |
| + a pty master registered | **FAIL - accept never fires again** | PASS |

So the final build removes only upstream's `setenv("EVENT_NOKQUEUE", ...)`,
letting libevent choose **poll**, and keeps `EVENT_NOPOLL`.

## The rest of the Darwin ABI traps

Each of these produced its own bug before being fixed; the fixes live in
`sysroot-overlay/usr/include/`:

| header | trap |
|---|---|
| `bits/errno.h` | `EAGAIN` 11 (Linux) vs 35 (Darwin): every `errno != EAGAIN` treats "try again" as fatal |
| `sys/socket.h` | `SOL_SOCKET` 1 vs `0xffff`: `sendmsg`+`SCM_RIGHTS` fails with `EINVAL`, so the client cannot hand its tty to the server |
| `fcntl.h` | `O_NONBLOCK`/`O_CLOEXEC` as above |
| `pwd.h` | Darwin inserts `pw_change`/`pw_class`: musl's layout made `pw_shell` read `pw_gecos` - tmux tried to exec a shell named "Mobile User" |
| `termios.h` | musl adds `c_line`; every offset after it differs |
| `sys/utsname.h` | Darwin `char[256]x5` vs musl `char[65]x6`: `uname()` overflows the caller's stack by ~890 bytes and corrupts adjacent buffers (tmux parsed `list-windows` as `liPad3,4`) |
| `bits/signal.h` | signal numbers, `SA_*`, `sigset_t` |
| `sys/ioctl.h` | `TIOCGWINSZ` and friends are completely different ioctls |
| `unistd.h` | `closefrom` does not exist on iOS 10; autoconf probes always succeed because the linker tolerates undefined symbols, so it must be disabled by hand and replaced by tmux's bundled copy - it aborts in the forked child of every new pane, visible only in `/var/mobile/Library/Logs/CrashReporter/*.ips` |

Debugging tips that actually worked, in order of usefulness:

1. **Read the crash reports first.** A dyld abort produces no other output;
   `Termination Description: DYLD, Symbol not found: _closefrom` ended days of
   guessing.
2. **Compare tmux with a minimal libevent program on the device.** When tmux
   hangs, a 60-line program that does the same registration pattern either
   reproduces it (libevent/platform bug) or passes (tmux logic bug).
3. **Instrument libevent itself.** A debug `fprintf` around `poll()` showing
   the fds, requested events and returned `revents` settles arguments about
   "lost wakeups" immediately.
